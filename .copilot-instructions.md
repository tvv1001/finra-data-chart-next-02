# Copilot Instructions for FINRA Network Graph

This repository is a Next.js + D3 graph application for FINRA/SEC network data. Use these conventions when generating changes, especially for graph interactions, node styling, and regulatory data behavior.

## Project Focus

- The main graph logic lives in src/lib/finra-graph.ts.
- UI is rendered via src/components/FinraGraph.tsx, with page setup in src/app/page.tsx.
- The graph is driven by D3 force simulation and DOM selections, not by React state.

## Coding Rules

- Keep changes localized: prefer editing src/lib/finra-graph.ts for graph behavior.
- Do not rewrite the app into a different framework or library.
- Use existing helper functions such as selectNode, renderNodeContents, refreshGraphColors, appendFetched, and injectNodesById.
- Preserve existing D3 patterns for simulation, nodeSel, linkSel, and SVG updates.
- Maintain current styling conventions for nodes, lines, and legend entries unless explicitly requested.
- Validate behavior changes against the current working UI state before documenting them as canonical.
- When updating docs or instructions, describe the implemented behavior exactly as it exists in code, not a preferred or historical version.
- Keep README and instruction files aligned with `src/lib/finra-graph.ts` and `src/app/globals.css` whenever graph interaction behavior changes.

## Graph Behavior

- Broker and Investment Adviser roles are distinct. Treat FINRA data as broker/broker-dealer registration and SEC data as adviser/IA registration.
- CRD records, disclosures, and registration status are primary signals for regulatory risk.
- The largest parent node should remain anchored when clicking other nodes.
- Default employed_by and controls lines should be green after the latest request.
- Selected connected lines should also use green when active.
- The currently selected node is tracked separately from hop-based highlight roots.
- `Clear Highlight` should remove normal hop highlights while keeping the selected node selected.
- `Trace Mode` and `Trace with Log` are distinct interaction modes and must not be collapsed into one behavior.

### Trace behavior contract

- `Trace Mode` should derive its endpoints from active selection context first:
  - `highlightedSelections`
  - then `selectedId`
  - then recent selection-log fallback only when fewer than two active endpoints exist
- `Trace with Log` should derive its path from the chronological `selectedNodesLog`
- Green trace (`trace-shortest`) means current regular-trace endpoints and, when available, the full distinct closed loop
- Purple trace (`trace-longest`) means the longest explicit non-circle forward route for the current regular trace
- If a complete green loop exists and there is no separate non-circle route, do **not** render a fallback purple line on that loop
- Nodes that are both green and purple should use the existing `trace-combined` treatment rather than a conflicting duplicate visual
- Any future edits to trace behavior must be validated in code and, when practical, with the live graph before updating README or instructions

## Regulatory Context

- B: Broker
  - A brokerage firm, also called a broker-dealer, buys and sells securities (stocks, bonds, mutual funds, and certain other investment products) on behalf of customers, for its own account, or both.
  - Individuals who work for broker-dealers are commonly referred to as brokers; they are the sales personnel for the firm.

- IA: Investment Adviser
  - An investment adviser is paid to provide advice about securities to clients, and may also manage portfolios or offer financial planning services.
  - It is common for a financial professional to act as both a broker and an investment adviser. This is why BrokerCheck includes investment advisers alongside brokers.

- PR: Previously Registered
  - A Previously Registered broker or brokerage firm is not currently licensed to act as a broker or as an investment adviser.
  - They may still provide other investment-related services if properly licensed for those activities.

- Disclosures
  - Disclosures include customer complaints, arbitrations, regulatory actions, employment terminations, bankruptcy filings, and certain civil or criminal proceedings involving the individual or firm.

- Use these definitions as the primary guidance for graph labels, node categories, tooltip text, and sidebar explanations. The app should not rely on external URL references for basic regulatory meaning.

## Data Pipeline (raw → merged/binary)

- Raw FINRA/SEC payloads live in `data/raw/` with filenames like `finra:individual:4240769.json`.
- The canonical rebuild pipeline is `pnpm data:rebuild`, which generates:
  - `data/national/` normalized cache files
  - `data/national/primed-cache/` and `data/primed-cache/` bundles
  - `data/cache-binary/` gzip binaries and manifests
- When re-importing raw files from the external source `/home/lenny/Dev/webDev/Data-finra-sec/data/raw/`, sync **only** into `data/raw/`.
- **Do not use or reference any `app/bak` folder** for raw or rebuilt data.
